# "있는데 왜 없다고 해?" — 누락 신고 조사 절차

베리맵 현황판에서 빈 칸인데 실제로는 등록돼 있는 경우, 그 링크 하나를 받고
무엇을 확인해서 무엇을 고치는지에 대한 절차서다. 다른 사람(또는 다른 세션)이
이 작업을 이어받을 때 이 문서만 읽으면 된다.

전제: `베리맵_로직.md`(매칭 사다리)와 `베리맵_상세흐름.md`(수집 흐름)를 먼저 읽을 것.

## 0. 작업 환경

- 폴더: `E:\varryup-main\varryup-main`
- 데이터: `data/verimap/`
- 대조(21번)는 **네트워크를 전혀 쓰지 않는다.** 이미 받아 둔 파일로만 계산한다.
  그래서 규칙을 몇 번을 고쳐도 다시 수집할 필요가 없다.


## 1. 제일 먼저 — 신선도 확인

**버그를 찾기 전에 이것부터 본다.** 수집은 새로 했는데 대조를 안 돌린 것뿐인
경우가 실제로 있었다(2026-10-30, No.114 BMW M3).

```bash
ls -l --time-style=+%F_%H:%M data/verimap/imweb_options_b2b.csv data/verimap/match_현황.csv
```

수집 파일이 `match_현황.csv`보다 **새것**이면 → 21번만 다시 누르면 끝.
코드는 건드리지 않는다.

## 3. 원본에 있나 확인

예: B2B 상품 453

```bash
cd data/verimap
python3 -c "
import json
d=json.load(open('imweb_options_raw_b2b.json',encoding='utf-8'))
for x in d:
    if str(x.get('prodNo'))=='453':
        print(x['name'])
        for od in x.get('options',[]):
            v=' / '.join(f\"{i['name']}={i['optionValue']['optionValueName']}\" for i in od['optionDetailInfoList'])
            print(' ',od.get('status'),'|',v)
"
```

- **원본에 있다** → 매칭 문제다. 4번으로.
- **원본에 없다** → 수집 문제다. 해당 채널 수집(11·12·14·15·18·22번)을 다시 돌린다.
  옵션 수집은 "확인필요분만" 받으므로, 새로 생긴 상품은 목록(11·12)을 먼저 돌려야 옵션 대상에 들어간다.

## 4. 대조가 그 상품을 어떻게 판정했나

```bash
grep ",453," data/verimap/match_명단.csv
grep ",453," data/verimap/match_확인필요.csv
```

`판정` 칸과 `비고` 칸에 이유가 적혀 있다. 판정별 처방:

| 판정 | 뜻 | 보통의 원인과 처방 |
|---|---|---|
| **후보다중** | 번호로 좁혔는데 코드표 여러 행이 남음 | 모델명이 안 붙은 것. `model_aliases.json`에 그 행의 다른 이름을 넣거나, 매칭 규칙을 본다 |
| **고아** | 코드표에 없는 부품번호 | 구 번호면 `part_aliases.json`에 `"704":"703"` 식으로. 오타면 상품 쪽을 고친다 |
| **미해결** | 번호를 못 뽑음 | 제목·옵션 표기가 정규식과 안 맞음. `extractParts`의 표기 예시를 늘린다 |
| **통합상품** | 전 차종 묶음으로 판정 | `isBundle` / 네이버 `bundle` 판정이 과했던 것(BMW X7 86행 사건) |
| **대상아님(...)** | 미러가 아니라고 판정 | `notMirror`가 과했던 것 |
| **명단에 아예 없음** | 레코드가 안 만들어짐 | 옵션 CSV에 그 상품이 없거나, 판매상태가 `판매중`이 아님 |

중요: 한 상품에 옵션이 있으면 **옵션이 상품명을 이긴다**(`byOption`). 옵션이 수집 안 된
상품은 제목의 코드 묶음 `[113,114,117,181]`만 읽고 후보다중으로 끝난다 — 이게 가장 흔한 원인이다.

## 5. 고친 뒤 반드시 — 회귀 검사

규칙을 느슨하게 하면 한 채널이 늘고 다른 채널이 줄어든다. 실제로 겪은 것:

- 브랜드 제거 실험 → 쿠팡 +10, 본사몰 −26 → 되돌림
- 일문 사전을 영문·한글 제목에도 적용 → 미국 −34, 본사몰 −19 → 일문에만 적용
- 낱말 경계 규칙 1·2차 시안 → 미국 −86 / −67 → 공백 자리를 기억하는 방식으로 해결

**고친 뒤 사본에서 돌려 채널별 숫자를 전부 비교한다. 하나라도 줄면 되돌린다.**

기준 숫자 (2026-10-30, 코드표 자동차 994행):

```
쿠팡 918 · 스마트스토어 942 · 본사몰 939 · B2B 911
해외몰(미국) 895 · 해외몰(일본) 733
국내 전 채널 850 · 어느 채널에도 없음 28
```

## 6. 코드로 못 고치는 경우 — 수동 확인

코드표가 한 차를 두 줄로 쪼개 놨다거나(해치백 / 해치백 S), 판단이 사람 몫일 때는
`data/verimap/manual_links.json`에 직접 적는다. 대조를 다시 돌려도 지워지지 않는다.

키는 `부품번호|모델명|세대|채널` 을 소문자·공백제거한 것:

```json
{
  "no.102번|mini쿠퍼해치백s|1세대|B2B": {
    "s": "ok",
    "v": "https://bb-store.co.kr/shop_view?idx=457"
  }
}
```

`v`에 `제목 | 링크` 형식으로 넣으면 현황판에 제목이 보이고 클릭하면 그 링크로 간다.
`s`는 `ok`(등록됨) 또는 `no`(확인했더니 진짜 누락).

**이 파일은 사람이 하나씩 확인한 것이라 다시 만들 수 없다. 덮어쓰지 말 것.**

---

## 7. 건드리면 안 되는 것

- **베리업 쪽 파일 전부.** 베리맵은 `scripts/verimap_*`, `src/ui/index_verimap.html`,
  `data/verimap/`, `베리맵.bat` 이다. 그 밖은 다른 사람 작업이다.
- 자격증명. 아임웹 OAuth 키는 환경변수로만 넘기고, 네이버 clientSecret은 Windows
  safeStorage에 있어서 네이버 수집기는 Electron으로 돌려야 한다.
- 다시 못 만드는 설정 7개: `config.json` `model_names.json` `model_aliases.json`
  `part_aliases.json` `verimap_links.json` `manual_links.json` `verimap_ui.json`
