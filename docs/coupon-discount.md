# 쿠폰 · 할인가 · 정가 (쿠팡 · 스마트스토어 · 아임웹 본사몰)

공식 API 문서로 확인한 결과와 앱에 붙인 것입니다. 2026-11-06에 정리했습니다.

앱이 몰에 쓰는 것은 판매가와 정가(취소선)뿐이고, 일괄 수정 [선택 변경 저장]으로만 나갑니다. 쿠폰은 앱이 만들지 않습니다.

## 1. 가격 정책 (11-06 최종)

11-05·11-06 표(일반·BSA 따로)는 11-06 소유자 결정으로 바뀌었습니다.
- 220,000·219,000 → 150,000 → 140,000 으로 맞춘 뒤, **판(BSA·일반) 구분 없이** 한 구조를 씁니다.
- 할인율 표기가 맞지 않는 것은 상관하지 않습니다.

| 몰 | 정가(취소선) | 판매가 | 2단계 | 3단계 (1회 한정) |
| :--- | ---: | ---: | ---: | ---: |
| 쿠팡 | 140,000 | 100,000 | 알람설정 할인 90,000 (−10,000) | 첫 구매가 80,000 (−10,000) |
| 스마트스토어 | 140,000 | 100,000 | 알람설정 할인 90,000 (−10,000) | 첫 구매가 80,000 (−10,000) |
| 아임웹 본사 | 140,000 | 100,000 | 정회원가 85,000 (−15,000) | 첫 구매가 80,000 |

- 모든 몰에 [무료배송 + 마감임박] 문구가 붙습니다. 이 문구는 상품명이나 상세 문구라 앱 범위가 아닙니다.
- **아임웹 본사는 앱으로 하지 않습니다**(11-06 "아임웹은 할 필요 없음"). 표의 아임웹 줄은 기록으로만 남깁니다.

## 2. 몰별로 API 로 되는 것과 손으로 할 것

### 2.1 쿠팡 — 판매가·정가는 API, 대상 지정 쿠폰은 API 에 없음

출처: `developers.coupangcorp.com/ko/api/promotions` 와 `/ko/api/products/change-the-base-price-for-discount-rate-at-an-item-level` (11-06 확인)

| 할 일 | 방법 |
| :--- | :--- |
| 판매가 | `PUT …/vendor-items/{id}/prices/{v}` (앱 사용 중) |
| 정가(취소선) | 할인율 기준가 `PUT …/vendor-items/{id}/original-prices/{v}` — 0원부터 10원 단위 (앱 사용, 11-06) |
| 즉시할인 쿠폰 | `POST /v2/providers/fms/apis/api/v2/vendors/{vendorId}/coupon` → `…/coupons/{couponId}/items`. 대상은 전체 고객(또는 로켓와우)뿐이고 `contractId` 가 필요합니다 |
| 다운로드 쿠폰 | `POST /v2/providers/marketplace_openapi/apis/api/v1/coupons` → `PUT …/coupon-items`. 내려받는 누구나 쓰며 1인 1일 발급 수를 정할 수 있습니다 |
| 알람설정·첫 구매 대상 쿠폰 | **API 없음.** WING 화면에서 대상 지정이 되는지 확인해야 합니다 |

### 2.2 스마트스토어 — 판매가·정가는 API(즉시할인), 쿠폰은 판매자센터

커머스API 공식 답변을 근거로 합니다(github `commerce-api-naver/commerce-api` 토론).
- #3199, #3465: 쿠폰 등록·조회 API 는 없습니다.
- #2997, #3349: 즉시할인의 위치는 `originProduct.customerBenefit.immediateDiscountPolicy.discountMethod { value, unitType: WON|PERCENT, startDate, endDate }` 입니다.
- #3888: 이 칸을 null 로 보내면 할인이 지워집니다.
- #1492: 목록 조회의 채널상품에 `salePrice` 와 `discountedPrice` 가 함께 옵니다.

| 할 일 | 방법 |
| :--- | :--- |
| 정가(취소선) + 판매가 | 원상품 `salePrice` = 정가, 즉시할인(원) = 정가 − 판매가. 원상품 GET → 전체 PUT (앱 사용, 11-06) |
| 알림받기 고객 쿠폰 −10,000 | 스마트스토어센터 › 혜택 등록 › 대상 '알림받기 고객' (판매자 FAQ 4398) |
| 첫 구매 쿠폰 −10,000 | 스마트스토어센터 › 혜택 등록 › 첫 구매 고객 대상 |

### 2.3 아임웹 본사 (앱으로 하지 않음 — 참고)

출처: `developers-docs.imweb.me/reference/openapi.json` (11-06 확인)
- `PATCH /products/{no}/price` 의 `price`·`originalPrice` 로 판매가와 정가를 씁니다.
- `PATCH /products/{no}/discount-info` 의 그룹 할인(정회원)으로 정회원가를 만듭니다.
- 쿠폰은 `POST /promotion/shop-coupon` 으로 만듭니다. 대상 `join`(가입 시 자동 발행)이 첫 구매에 가장 가깝습니다.

## 3. 앱에 붙인 것

### 3.1 일괄 수정 — 값 출처 '가격 정책' (쿠팡 · 스마트스토어)

> 2026-11-09: 일괄 수정의 값 출처 드롭다운을 없앴습니다(판매가 열은 [칸][통화][↓]). 지금은 이 절의 계산을 부르는 화면이 없습니다. `policyPrice` 와 저장 쪽 정가(`newList`) 처리는 코드에 남아 있습니다.

계산은 `src/utils/price_policy.js` 의 `policyPrice` 가 합니다.
- 판매 단위 줄에 판매가 100,000 과 정가 140,000 을 넣습니다. 판매 단위 줄은 쿠팡 옵션('1개' = 1set)과 네이버 상품 한 줄(기본가)입니다.
- 아래 줄은 건너뜁니다.
  - 운전석·조수석
  - 오토바이 상품
  - 쿠팡에서 지금 값의 절반 아래로 내려가는 줄. 쿠팡은 50% 넘게 내리면 그 상품째 저장이 멈추고, 이런 줄은 대개 가격 오타입니다.
- [선택 변경 저장]이 판매가 작업에 정가(`newList`)를 함께 실어 보냅니다.
  - 정가가 섞이면 확인 창이 늘 뜨고, 정가 건수와 금액을 보여 줍니다.
  - 판매가가 이미 같아도 정가는 보냅니다.
  - 다른 값 출처(직접 입력·환율가)로 덮으면 정가는 버립니다.
- **쿠팡**: 검사(재조회 비교·50% 상한·정가 ≥ 판매가)를 다 마친 뒤 할인율 기준가를 쓰고, 그다음 판매가를 씁니다(`coupang.js changeItemPrice`).
- **쿠팡 순서**: 기준가가 지금 판매가 이상이면 기준가를 먼저 쓰고, 아니면 판매가를 먼저 씁니다. 기준가가 판매가보다 낮은 순간이 생기지 않게 하려는 것입니다.
- **네이버**: 원상품 판매가를 정가로, 즉시할인(원)을 정가 − 판매가로 한 번에 PUT 합니다.
  - **앱의 네이버 '판매가'는 어느 화면이든 손님이 내는 할인 뒤 값입니다**(일괄 수정·상품 수정 탭·6몰 표). 목록은 `discountedPrice`, 원상품은 `naverFinalPrice` 로 읽습니다.
  - 쓰기는 모두 `naver_products.js setNaverPrice` 한 곳을 지납니다.
    - 정가 없이 판매가만 바꾸면 할인이 걸린 상품은 정가를 두고 할인만 바꿉니다. 판매가를 `salePrice` 에 바로 쓰면 걸린 할인이 한 번 더 빠지기 때문입니다(11-06 리뷰: 6몰 표에 100,000 을 넣으면 60,000 이 되던 것).
    - 정가보다 높게 바꾸면 할인을 null 로 지웁니다. 기간 밖 할인은 건드리지 않습니다.
    - 할인 기간(startDate·endDate)과 모바일 할인은 남기고 금액만 바꿉니다.
    - 판매가가 그대로면 아무것도 바꾸지 않습니다. 상품명만 고칠 때 퍼센트 할인이 원 할인으로 바뀌지 않게 하려는 것입니다.
  - 복사등록: 템플릿에 원 즉시할인(정가 구조)이 있으면 입력한 판매가를 할인 뒤 값으로 맞춥니다. 퍼센트 할인은 예전처럼 그대로 물려줍니다.
- 쿠폰은 화면 안내만 합니다: 알람설정 할인 90,000(−10,000) · 첫 구매가 80,000(−10,000).

### 3.2 일괄 수정 — [데이터 갱신]

[상품 목록 조회] 옆에 있습니다. 나라 화면에서는 숨깁니다.
- 네이버·쿠팡 목록의 5분 캐시를 건너뜁니다. 아마존·eBay 는 전체 목록 동기화를 먼저 합니다.
- 보이는 쪽만이 아니라 모든 상품의 현재가를 몰 API 로 다시 읽습니다. 읽은 값은 몰의 저장본에 들어갑니다(쿠팡 판매가 캐시, 아마존·eBay 목록 캐시).
- 끝나면 '목록 값과 현재가가 달랐던 행' 수를 알려 줍니다. 몰에 쓰는 동작은 없습니다.

### 3.3 나라 탭 — BSA 표기 없는 본사 상품

`country_sync.js referencePrices(rows, edition)` 를 고쳤습니다.
- 조합 문구에 판이 없으면 `editionFor`(옵션·상품명 표기 → 쿠팡 옵션 문구 → 카탈로그 `bsa` 칸이 모두 같을 때)로 정합니다.
- 예: 2142 크라이슬러 200C [No.4013] 는 BSA판인데 표기가 없었습니다. 그래서 짝을 못 맞추고, 일반 짝에 BSA 값이 들어갈 수 있었습니다.

## 4. 남은 것 · 주의

- 쿠팡 정가(할인율 기준가)는 지금 값을 읽지 않고 다시 씁니다. 같은 값이면 바뀌는 것이 없습니다. 쓰기 뒤 확인도 판매가만 합니다.
- 퍼센트 즉시할인의 원 단위 끝자리 처리는 확인하지 못해 버림으로 계산합니다. 네이버 목록의 `discountedPrice` 와 몇 원 다를 수 있고, 그 차이는 [데이터 갱신]의 '달랐던 행' 수에만 보입니다.
- 나라 탭은 네이버를 본사 **운전석** 가격으로 맞춥니다. 정책을 적용한 네이버 상품에 [본사 값으로 맞추기]를 누르면 정가는 그대로 두고 할인만 늘려 운전석 가격이 됩니다. 정책을 쓴 뒤에는 네이버에 이 버튼을 쓰지 마세요.
- 네이버는 기본가가 운전석가이고 조수석은 −10,000 추가금입니다. 정가 140,000·판매가 100,000 은 그 상품의 기본가(운전석)에 걸립니다(11-06 사용자 지정).
- 쿠팡 '알람설정·첫 구매' 대상 쿠폰이 WING 에도 없으면, 다운로드 쿠폰으로 대신할지 정해야 합니다.
