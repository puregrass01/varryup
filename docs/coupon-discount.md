# 쿠폰 · 할인가 (쿠팡 · 네이버 · 아임웹 본사몰)

2026-11-06 정리. 공식 API 문서를 직접 확인한 결과와 앱에 붙인 것(범위 A)입니다. 앱이 몰에 쿠폰을 만들거나 정가를 바꾸는 호출은 없습니다.

## 1. 가격 정책 (사용자 표, 11-05 · 11-06)

| | 정가 | 판매가 | 2단계 | 3단계 (1회 한정) |
| :--- | ---: | ---: | ---: | ---: |
| 본사 자사몰 일반 | 140,000 | 100,000 | 정회원가 85,000 | 첫 구매가 70,000 |
| 본사 자사몰 BSA | 180,000 | 135,000 | 정회원가 120,000 | 첫 구매가 105,000 |
| 스토어팜 · 쿠팡 일반 | 140,000 | 100,000 | 알림설정 90,000 | 첫 구매가 80,000 |
| 스토어팜 · 쿠팡 BSA | 180,000 | 135,000 | 알림설정 125,000 | 첫 구매가 115,000 |

두 버전 모두 [무료배송 + 마감임박] 문구가 붙습니다.

**표에서 읽히는 점**
- 판의 차이는 정가와 판매가에만 있습니다. 할인 금액은 판과 상관없이 같습니다.
  - 자사몰: 정회원 −15,000원, 첫 구매 −15,000원
  - 스토어팜 · 쿠팡: 알림설정 −10,000원, 첫 구매 −10,000원
  - 그래서 쿠폰은 몰마다 정액 쿠폰 한두 개면 됩니다. 판별로 나눌 필요가 없습니다.
- 할인율 표기는 한 가지 규칙으로 계산되지 않습니다(손으로 적은 값으로 보입니다).
  - 90,000→80,000 은 11.1% 인데 12% 로 적혀 있습니다.
  - 120,000→105,000 은 12.5% 인데 12% 로 적혀 있습니다.
  - 135,000→125,000 은 7.4% 인데 8% 로 적혀 있습니다.
  - 몰 화면의 할인율은 몰이 정가와 판매가로 직접 계산합니다. 앱은 미리보기에서만 할인율을 보여 주며, 실제보다 크게 쓰지 않도록 소수점을 버립니다.

## 2. 몰별로 API 로 되는 것과 손으로 할 것

### 2.1 아임웹 본사몰 — 거의 전부 API 로 됩니다

출처: `https://developers-docs.imweb.me/reference/openapi.json` (11-06 확인)

| 할 일 | 방법 | 비고 |
| :--- | :--- | :--- |
| 판매가 | `PATCH /products/{no}/price` 의 `price` · 조합가 `option-details` | 지금 일괄 수정이 쓰는 경로입니다 |
| 정가(취소선) | 같은 `PATCH /products/{no}/price` 의 `originalPrice` | 앱은 아직 이 칸을 보내지 않습니다 |
| 정회원가 | `PATCH /products/{no}/discount-info` 의 `period=Y`, `periodData.targetGroups[{ groupType:'group', groupCode:<정회원>, discountAmount:15000, discountType:'price' }]` | 할인 설정 전체(쿠폰 · 적립금 · 쇼핑등급 여부)를 함께 보내는 방식입니다. 그래서 현재 값을 읽어 `discountInfoFrom` (imweb_b2b.js) 으로 다시 만들어야 합니다. 정회원 그룹 코드는 `GET /member-info/groups` 로 찾습니다 |
| 첫 구매 쿠폰 | `POST /promotion/shop-coupon` 으로 `type:'auto'`, `basicSetting.targetType:'join'`(가입 시 자동 발행), `saleType:'price'`, `amount:15000`, `memberLimitCount:1` | 아임웹 자동 쿠폰의 대상에는 '첫 구매'가 따로 없습니다. `order` 는 첫 주문이 끝난 **뒤**에 다음 구매용으로 발행되는 쿠폰입니다. 그래서 가입 쿠폰이 가장 가깝습니다. 단, 가입은 했지만 아직 사지 않은 기존 회원은 받지 못합니다 |
| 쿠폰 조회 · 발급 | `GET /promotion/shop-coupon`, `POST …/{code}/issue` · `/issue/group` | 필요하면 정회원 그룹에 일괄 발급할 수 있습니다 |
| 쇼핑등급 할인율 | API 없음(`GET /member-info/grades` 조회만 됩니다) | 등급 할인을 쓰려면 관리자 화면에서 설정합니다 |

### 2.2 쿠팡 — 가격 · 정가는 API, 대상 지정 쿠폰은 API 에 없음

출처: `https://developers.coupangcorp.com/ko/api/promotions` · `/ko/api/products/change-the-base-price-for-discount-rate-at-an-item-level` (11-06 확인)

| 할 일 | 방법 | 비고 |
| :--- | :--- | :--- |
| 판매가 | `PUT /vendor-items/{id}/prices/{v}` | 지금 쓰는 경로입니다 |
| 정가(취소선) | 할인율 기준가 변경 `PUT …/vendor-items/{id}/original-prices/{v}` | 앱에 아직 없습니다 |
| 즉시할인 쿠폰 | `POST /v2/providers/fms/apis/api/v2/vendors/{vendorId}/coupon` (`contractId`, `type` RATE/PRICE/FIXED_WITH_QUANTITY, `discount`, `maxDiscountPrice`, `startAt`/`endAt`) → `POST …/coupons/{couponId}/items` 로 vendorItemId 추가(비동기, `requestedId` 로 결과 확인) | 대상은 **전체 고객**(또는 로켓와우)뿐입니다. 결국 모든 구매자가 할인가를 보게 됩니다 |
| 다운로드 쿠폰 | `POST /v2/providers/marketplace_openapi/apis/api/v1/coupons` (`policies[]`: `typeOfDiscount`, `discount` 10원 단위, `minimumPrice`, `maximumPerDaily` 1인 1일 발급 수) → `PUT …/coupon-items` | 내려받는 누구나 씁니다. 상품 추가에 실패하면 쿠폰이 파기됩니다 |
| 계약 · 예산 | `GET …/contract/list`, 예산 조회 | 쿠폰을 만들려면 `contractId` 가 꼭 있어야 합니다 |
| '알림설정 고객' · '첫 구매 고객' 대상 | **API 없음** | WING 화면에 이런 대상 지정 쿠폰이 있는지 확인이 필요합니다. 없다면 다운로드 쿠폰(1인 1일 1장)으로 대신할지 정해야 합니다 |

### 2.3 네이버 스마트스토어 — 쿠폰은 전부 판매자센터

커머스API 공식 답변을 확인했습니다.
- github `commerce-api-naver/commerce-api` 토론 #3199(2026-01): 할인 쿠폰 등록 API 는 제공하지 않습니다. 알림받기 고객 등 대상 지정 쿠폰은 스마트스토어센터에서 발급하라는 답이었습니다(판매자 FAQ 4398).
- 같은 저장소 토론 #3465(2026-04): 혜택 조회 · 수정 API 도 없습니다.

| 할 일 | 방법 | 비고 |
| :--- | :--- | :--- |
| 판매가 | 원상품 GET → `salePrice` → 전체 PUT | 지금 쓰는 경로입니다 |
| 정가(취소선) | 원상품 `customerBenefit.immediateDiscountPolicy`(판매자 즉시할인)로 표시합니다. `salePrice`=정가, 할인=정가−판매가 | **주의**: 즉시할인을 걸면 `salePrice` 가 정가가 됩니다. 그런데 앱의 판매가 쓰기(일괄 수정 · 나라 탭)는 `salePrice` 에 판매가를 넣습니다. 손으로든 API 로든 즉시할인을 걸면 이중 할인이 됩니다. 앱의 네이버 가격 모델을 함께 바꿔야 합니다 |
| 알림받기 고객 쿠폰 −10,000 | 스마트스토어센터 › 혜택 등록 › 대상 '알림받기 고객' | 손으로 · 한 번만 만들면 됩니다 |
| 첫 구매 쿠폰 −10,000 | 스마트스토어센터 › 혜택 등록 › 첫 구매 고객 대상 | 손으로 · 대상 선택지는 화면에서 확인해야 합니다 |

### 2.4 몰마다 같이 걸리는 것

- [무료배송 + 마감임박] 은 상품명이나 상세 문구입니다. 이번 범위가 아닙니다.
- 네이버는 한쪽씩 팝니다. 기본가가 운전석가이고 조수석은 −10,000 추가금입니다(country_sync.js). 쿠팡 · 아마존 · eBay 는 1set 단위로 팝니다. 표의 금액은 1set 가격으로 봅니다(11-06 범위 A 승인 때의 기본값). 그래서, 네이버 · 운전석 · 조수석 가격은 단품가 규칙이 정해질 때까지 그대로 둡니다(§4).


## 3. 앱에 붙인 것 (범위 A, 11-06 구현)

몰에 새로 쓰는 호출은 없습니다. 판매가는 기존 [선택 변경 저장]으로만 나갑니다. 정가 · 쿠폰은 §5 대로 손으로 설정합니다.

### 3.1 계산 모듈 `src/utils/price_policy.js`

순수 함수라서 메인과 화면이 같이 씁니다.

- `POLICY` 에 §1 표를 그대로 둡니다. 각 칸은 `{ list 정가, sale 판매가, tier2, tier3 }` 입니다.
- `POLICY_SCOPES` 는 정책을 쓸 수 있는 범위입니다. 아임웹 본사(`imweb`)와 쿠팡(`market`)뿐입니다.
- `floorTo(won, unit)` 는 천 원(기본) 또는 만 원 단위로 내립니다.
  - 표의 값은 이미 천 원 단위라서 범위 A 에서 이 함수가 바꾸는 값은 없습니다.
  - 할인율로 값을 만들게 되면(단품가 규칙 · 범위 B) 이 함수로 끝자리를 맞춥니다.
- `percentOff(from, to)` 는 할인율을 실제보다 크게 쓰지 않도록 소수점을 버립니다. 정수로 계산합니다.
- `editionFor(scope, row, catalog)` 가 판을 정합니다. 근거는 아래 순서로 봅니다.
  1. 옵션 문구 · 상품명의 표기를 봅니다(`editionOf`: BSA 있음/없음, BSA O/X, With/No BSA, あり/なし).
  2. 쿠팡은 옵션 문구에 BSA 가 없으면 일반판으로 봅니다(나라 탭 · 인덱스와 같은 규칙).
  3. 차량 카탈로그를 봅니다(`data/vehicle_catalog.json`). 같은 상품번호의 `bsa` 칸이 모두 'BSA 가능'이면 BSA, 모두 아니면 일반입니다. 'Bsa 제작 필요'와 브라켓 · 크기 메모는 '아님'으로 봅니다. 섞여 있으면 판을 모르는 것으로 보고 건너뜁니다.
  - **아임웹은 표기가 없다고 일반으로 보지 않습니다.** BSA판을 따로 만든 상품은 옵션에도 이름에도 BSA 가 없기 때문입니다.
- `policyPrice(scope, row, { hasCombos, catalog })` 는 `{ price, result } | { skip }` 을 돌려줍니다. 1set 줄만 채우고, 아래 줄은 이유를 적고 건너뜁니다.
  - 아임웹 기본가 줄(조합이 있는 상품)
  - 운전석 · 조수석
  - 오토바이 상품
  - 판을 모르는 줄
  - 쿠팡에서 정책가가 지금 값의 절반 아래인 줄. 쿠팡은 50% 넘게 내리면 그 상품째 저장이 멈춥니다.
- `couponGuide(scope)` 는 판매자센터에서 만들 쿠폰 금액을 한 줄로 만듭니다.

### 3.2 화면 — 일괄 수정의 값 출처 '가격 정책'

- [가격 적용] 옆의 값 출처(직접 입력 · 환율가)에 '가격 정책'을 더했습니다. 아임웹 본사 · 쿠팡 범위에서만 보입니다.
- 이 값 출처를 고르면 판매가 칸이 잠기고, 줄마다 판 · 구성을 읽어 '판매가 덮어쓰기' 칸을 채웁니다.
  - 처리 결과 칸에 근거를 적습니다. 예: `정책 일반 1set 100,000 (정가 140,000 대비 28%↓ · 판: 카탈로그 No.101 BSA 없음)`
  - 건너뛴 줄에는 `정책 건너뜀: …` 이라고 적습니다.
- 상품 한 줄이 옵션 여러 줄로 펼쳐져도, 줄마다 값을 따로 정하므로 그대로 채웁니다.
- 상태 줄에는 채운 행 수, 건너뛴 이유별 개수, 판매자센터 쿠폰 금액을 보여 줍니다.
- 보내기는 [선택 변경 저장]만 합니다. 쓰기 직전 현재가 재조회, 변경폭 상한, 결과 CSV 가 그대로 적용됩니다.
- 쿠팡 · 네이버는 나라 탭의 [본사 값으로 맞추기]로도 맞출 수 있습니다. 본사몰과 스토어팜 · 쿠팡의 정가 · 판매가가 같기 때문입니다. 단, 네이버는 운전석가 기준입니다.

### 3.3 스냅샷 대조 (11-06, `data/verimap` 의 본사몰 옵션 · 쿠팡 아이템)

**본사몰 1set 줄 244개**
- 판을 정해 채운 줄은 212개입니다. 일반 158줄은 모두 지금 150,000, BSA 54줄은 모두 지금 220,000 이어서 판 판정과 기존 가격이 100% 맞았습니다.
  - BSA 54줄 가운데 23줄은 표기가 없어 카탈로그로 정했습니다.
- 건너뛴 줄은 32개입니다. 카탈로그에서 BSA 가능 · 불가가 섞인 줄이 31개, 카탈로그에 번호가 없는 줄이 1개입니다. 이 줄들은 '직접 입력'으로 넣습니다.

**쿠팡 1,534줄**
- 일반 150,000대와 BSA 220,000대가 대부분 맞았습니다.
- 맞지 않는 줄은 대개 옵션 표기 문제였습니다.
  - BSA 표기가 없는데 220,000 인 줄은 절반 아래 규칙으로 건너뜁니다.
  - BSA 표기가 있는데 150,000 인 줄은 표기를 따라 135,000 을 넣습니다.
- 가격 오타 2줄(1,500,000 · 2,090,000)이 있었습니다.
- 그 밖에 오토바이 58줄, 번호를 하나로 못 읽은 35줄을 건너뜁니다.
- 카탈로그로 쿠팡 판을 다시 확인하는 방법은 쓰지 않았습니다. 표기 없는 줄 중 카탈로그가 'BSA만'이라고 한 29줄 가운데 25줄이 일반판 가격이어서 오히려 틀렸습니다.

## 4. 아직 정하지 않은 것 (다음 범위)

- **단품가 규칙** — 본사몰 운전석 · 조수석 조합가와 네이버 기본가(운전석)를 무엇으로 할지 정해야 합니다.
  - 지금 값 유지, 1set 할인율만큼 낮춰 `floorTo` 로 내림, 네이버도 1set 판매 중에서 고릅니다.
  - 정해지면 `policyPrice` 의 운전석 · 조수석 분기와 `POLICY_SCOPES.naver` 를 채웁니다.
- **범위 B: 정가(취소선) 쓰기**
  - 쿠팡은 할인율 기준가 API, 아임웹은 `originalPrice` 를 씁니다. 아임웹 정회원 그룹 할인(`discount-info`)도 여기에 들어갑니다.
  - 새 쓰기 경로라서 실상품 한 개로 확인할 승인이 필요합니다.
  - 네이버 즉시할인은 앱의 네이버 가격 모델(`salePrice`=판매가)을 함께 바꿔야 합니다.
- **범위 C: 쿠폰 API**
  - 아임웹 가입 쿠폰을 API 로 만들고, 쿠팡 쿠폰 생성과 vendorItem 일괄 추가를 붙입니다(`contractId` 필요).
- **쿠팡 대상 지정 쿠폰** — 쿠팡에서 '알림설정 · 첫 구매' 대상 쿠폰을 쓸 수 없다면 다운로드 쿠폰(누구나 1인 1일 1장)으로 대신할지 정해야 합니다.

## 5. 판매자센터에서 손으로 할 것 (범위 A)

몰마다 정액 쿠폰 한두 개입니다. 일반판 · BSA판의 금액이 같으므로 판별로 나누지 않습니다.
