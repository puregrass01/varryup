# 베리맵이 어떻게 돌아가는가

작성 2026-10-22. 코드를 열기 전에 이 문서를 먼저 읽으면 왜 그렇게 짰는지가 보인다.

## 0. 푸는 문제

채널 네 곳(쿠팡 · 스마트스토어 · 본사몰 · B2B)에
**코드표의 차종이 전부 올라가 있는가**를 매일 확인하는 것. 빠진 것을 찾는 게 목적이지
재고나 가격을 보는 게 아니다.

### 왜 어려운가 — 조인 키가 없다

기준이 되는 코드표는 한 행이 "차종 하나"다. 예를 들면

```
행 2   No.101번   BMW   1시리즈   2세대   12.03~19.05
행 11  No.101번   BMW   5GT      6세대 파생   10.04~17.08
```

둘 다 `No.101번`이다. **부품번호는 '부품'을 가리키지 '행'을 가리키지 않는다.**
코드표 994행에 부품번호는 598가지뿐이고, 한 번호가 최대 13행에 걸린다.

채널 쪽도 모양이 제각각이다.

- 쿠팡: 상품 1개 : 차종 N개 (차종이 옵션으로 들어 있다)
- 스마트스토어: 상품 1개 : 차종 1개, 옵션 축이 셋 (모델명 / 상품선택 / 운전석·조수석)
- 본사몰: 코드가 상품명에 `[No.101]` 로, 구성(운전석·1set)은 옵션에
- B2B: 한 상품에 코드 여러 개를 `[1110,1113,1125]` 로 나열

그래서 "부품번호로 조인" 이 안 된다. 번호로 후보를 좁힌 뒤
**모델명 · 연식 · 세대로 한 행까지 줄이는 사다리**가 이 프로그램의 핵심이다.

---

## 1. 전체 흐름

```
[1]  코드표 불러오기      구글시트 → codetable.json      (verimap_load_codetable.mjs)
[2]  채널별 수집          각 API → *_raw.json / *.csv     (verimap_collect_*.mjs)
[3]  대조                 위 둘을 맞춤 → match_*.csv      (verimap_match.mjs)
[4]  보기                 현황판 창                        (src/ui/index_verimap.html)
```

수집과 대조를 나눈 이유는 **추출 규칙을 고칠 때 다시 받지 않기 위해서**다.
원본(`*_raw.json`)을 항상 남기고, 대조는 네트워크를 전혀 쓰지 않는다.
실제로 이 규칙 덕에 일문 모델명 사전·별칭·낱말 겹침을 붙이는 동안
한 번도 재수집하지 않았다.

## 2. 코드표 쪽 (verimap_load_codetable.mjs)

구글시트를 CSV 로 내보내 읽고 다음을 정규화한다.

**부품번호** `No.101번` · `No.H103-2번` · `No.B1501번`
접두 글자는 제조사 표시다 — H 현대 · K 기아 · R 르노 · S 쉐보레 · Y 쌍용 · B 오토바이,
없으면 수입차. 자동차 994행의 분포는 접두없음 718 · H 94 · K 72 · S 36 · R 23 · Y 23.

**한 칸에 번호가 둘인 경우**
```
No.703번(옵)
구 704번(bsa)
```
원본 코드표에는 이렇게 현행 번호와 폐기된 구 번호가 같이 적힌 행이 있다.
전부 거둬 같은 행을 가리키게 한다. 다만 **기준 시트로 추출될 때 구 번호가 떨어져 나가므로**
실제로는 `part_aliases.json`(구 번호 → 현행 번호)로 보완한다. 현재 6개:
704→703 · 705→702 · 709→707 · 1116→5044 · K122→K121 · Y103→Y102.

**연식** `12.03~19.05` · `99.03~03.03` · `16~` · `2020. 3. 4 ~ 현재`
두 자리 연도의 세기 판단 임계값은 **30**이다. 90 으로 잡으면 `82~94`(갤로퍼류)나
`89.07~00.08` 이 시작>종료가 되어 30행이 깨진다. 끝이 열려 있으면 999912 로 둔다.

**세대** `3세대 전기형` · `1세대/2세대` · `6세대 파생`
숫자 · 전기/초기/중기/후기 · 페이스리프트를 따로 뽑는다.
`1세대/2세대` 처럼 둘을 겹쳐 쓴 행은 숫자가 **앞의 것 하나로만** 읽힌다(18행). 3.1절에서 다시 언급한다.

## 3. 대조 (verimap_match.mjs) — 이 프로그램의 심장

채널 데이터를 **"적합 단위"** 한 줄씩으로 편다. 한 줄 = 한 상품의 한 차종.
현재 15,107줄이다. 각 줄마다 아래를 거친다.

### 3.0 대상에서 뺄 것부터 가린다

`notMirror()` 로 품목이 다른 것을 먼저 떨군다 — 사이드스텝(스타포쉬) · BSA 감지센서 ·
와이퍼 · 테스트/더미 상품. `isBundle()` 은 `전 차종` · `공동구매` 를 '통합상품'으로 묶는다.
한 상품에 모든 차종을 몰아넣은 것이라 차종 단위로 셀 수 없다.

판매상태가 `판매중` 으로 시작하지 않으면 대상에서 뺀다. **여기서 한 번 크게 틀렸다** —
쿠팡 옵션ID나 재고 조회가 안 되는 것을 `판매불가` 로 묶어 97건을 통째로 뺐는데,
옵션ID는 재고 조회에만 필요한 것이지 안 팔린다는 뜻이 아니었다. 구매 페이지가 멀쩡히
살아 있는 상품이 섞여 있었다. 지금은 `판매중(옵션ID없음)` 으로 꼬리표만 붙이고 대조한다.
등록 여부를 보는 게 목적이므로 **재고를 모른다고 빼면 안 된다.**

### 3.1 부품번호 추출

표기가 채널마다, 같은 채널 안에서도 제각각이다.

```
쿠팡     No.906-1세대(26.04~)BSA  ·  No.H149[ 1세대/24.04]BSA  ·  [B313] 1세대/24~
네이버   26.04~현재[No.906번]BSA  ·  🔶23~[No.1601]
B2B      [1110,1113,1103,1125]   ·  [K150,K151]
```

세 가지 규칙을 순서대로 본다 — `No.` 접두, 대괄호, 맨몸 접두(`H108-1`).
대괄호 안의 쉼표 나열은 먼저 풀어 코드 여러 개로 만든다.

맨몸 접두만 **3자리로 좁혔다.** `BMW R1250RT`(오토바이 모델명)나 `GSX-S1000` 을
번호로 오해했기 때문이다. 오토바이에는 `No.B1501번` 처럼 B+4자리가 실제로 있어
B 만 4자리까지 받는다. `No.` 나 대괄호로 표시된 번호는 사람이 번호라고 적은 것이므로
4자리도 그대로 믿는다.

`-숫자` 뒤에 `세대` 가 오면 서브번호가 아니라 세대 표기다(`No.H110-3세대`).

### 3.2 매칭 사다리 — 순서가 중요하다

부품번호로 후보 행을 모은 뒤, 아래 순서로 한 행까지 좁힌다.
**각 단계는 "딱 하나로 줄었으면 확정, 아니면 좁히기만 하고 다음 단계"** 로 동작한다.

```
1. 부품번호 유일        후보가 애초에 1행이면 끝
2. 모델명              ← 연식·세대보다 먼저
3. 연식                정확히 일치 → 시작연도만 일치
4. 세대                숫자 일치
5. 낱말 겹침            후보 중 딱 한 행만 그 낱말을 가질 때
6. 후보가 같은 차종      모델명·세대가 전부 같으면 전부 등록으로
```

**왜 모델명이 먼저인가.** 처음엔 연식 → 세대 → 모델명 순서였는데,
`BMW X1 [101] 2세대` 가 X1 행이 아니라 `1시리즈 2세대` 행에 붙었다.
코드표의 X1 행은 세대가 `1세대/2세대` 로 적혀 있어 숫자가 1 로만 읽히는 탓에
세대 2 로 거르는 순간 X1 이 떨어져 나갔다. 모델명을 먼저 보면 바로 X1 으로 간다.

**모델명 비교는 네 겹이다.**
- 코드표 국문 모델명
- 코드표 영문 모델명 칸(`modelAlt`)
- 다국어 표기 시트에서 **부품번호+국문모델명으로 짝지은** 공식 영문·일문 이름 (`model_names.json` 의 `pair`, 1044개)
- 손으로 적은 별칭 (`model_aliases.json`)

여럿이 걸리면 **더 구체적인 이름이 이긴다.** `해치백 S` 는 `해치백` 도 품고 있어 둘 다
걸리는데, 제목이 `MINI 쿠퍼 해치백 S` 면 긴 쪽이 맞다. 이 규칙 하나로 본사몰이 19행 올랐다.

**일본몰은 사전으로 번역한다.** 코드표에 일문 모델명 칸이 없어서 `BMW 2シリーズ` 가
`2시리즈` 와 안 붙는다. 다국어 시트에서 일문 차량명 625개를 뽑아
(`model_names.json` 의 `jp2ko`) 가타카나가 든 제목에만 적용한다.
**한글·영문 제목에까지 쓰면 안 된다** — 사전의 짧은 이름이 엉뚱하게 걸려
미국 −34행, 본사몰 −19행이 깎였다. 영문 제목은 코드표 영문 칸으로 이미 붙는다.

**낱말 겹침(5단계)** 은 이름 전체가 포함돼야 붙는 비교로 `Porsche Cayman` 이
코드표 `718카이맨` 과 안 붙는 문제를 푼다. 그 차종에서만 쓰는 낱말(`cayman` · `ghibli`)이
후보 중 딱 한 행에서만 나오면 그 행으로 본다. 둘 이상이면 손대지 않는다 —
엉뚱하게 붙느니 후보다중으로 남기는 게 낫다. 숫자는 낱말에 붙여서 본다.
떼면 `6시리즈` 가 `시리즈` 가 되어 1시리즈와 겹친다(실제로 오매칭했다).

**6단계**는 코드표에 같은 내용이 두 줄 있을 때를 위한 것이다.
`No.339번 벤츠 S클래스 7세대 전기형` 이 191행·194행에 똑같이 들어 있어
게시물이 `7th gen Early model [No.339]` 라고 명확히 적어도 어느 줄인지 못 고른다.
모델명·세대가 전부 같으면 어느 쪽에 붙든 결과가 같으므로 전부 등록으로 표시한다.

### 3.3 판정

```
확정        한 행으로 좁혀짐
후보다중     여러 행이 남음 — 사람이 봐야 한다
고아        코드표에 없는 부품번호
미해결      부품번호를 찾지 못함
통합상품     전 차종 묶음 — 차종 단위로 셀 수 없음
대상아님     품목이 다름(사이드스텝·센서·와이퍼) 또는 테스트 상품
```

후보다중과 고아는 `match_확인필요.csv` 로 따로 뺀다.

## 4. 채널별로 다르게 다뤄야 하는 것

**쿠팡** 상품 1개에 차종이 옵션으로 여러 개. 목록만으로는 차종을 알 수 없어
상세를 상품마다 받아야 한다(초당 5회 제한, 1,200개면 8분). 상세·재고를 각각
한 달 캐시한다. 목록만 받는 실행이 상세를 덮어쓰지 않도록 이전 상세를 옮겨 둔다.

**스마트스토어** 상품명에 번호가 없다(1,049개 중 0개). 번호는 옵션에만 있어
채널상품 상세를 받아야 한다. 옵션 축이 `모델명 / 상품선택 / 운전석·조수석` 셋이다.

**본사몰** 코드는 상품명에, 구성(운전석·조수석·1set)은 옵션에. 옵션 축 이름이
B2B 는 `구성`, 본사몰은 `구성 선택` 이라 **정확히 일치로 찾으면 964행이 통째로 빈다.**
느슨하게 찾는다. 상품은 `내 차 찾기 ver2` 카테고리만 받는다(1,644개 중 964개).

**B2B** 한 상품에 코드를 여러 개 나열하고, 연식·세대는 제목이 아니라 옵션에 있다.
`1셋` 상품과 `운전석/조수석` 상품이 따로 있어 짝을 찾아야 한다(`modelKey()`).

## 5. 사람이 손대는 세 파일

| 파일 | 하는 일 |
|---|---|
| `part_aliases.json` | 구 번호 → 현행 번호 (원본 코드표에만 있는 정보) |
| `model_aliases.json` | 모델명 별칭 — 제목이 시트의 공식 이름과 다를 때 |
| `manual_links.json` | 사람이 눈으로 확인한 표시 (등록/누락 양방향) |

셋 다 **대조만 다시 돌리면 바로 먹는다.** 재수집도 시트 재내보내기도 필요 없다.

수동 확인은 열쇠가 `부품번호|모델명|세대|채널` 이다. 행 번호를 쓰면 코드표에 행이
끼어들 때 엉뚱한 차종에 붙어서 그렇게 했다. 994행 중 987개가 고유하다.

```
match_명단.csv     적합 단위 15,107줄 전부. 판정과 그 이유가 적혀 있다 — 디버깅은 여기서

```

현황판 칸을 누르면 그 상품으로 열린다. 주소 틀은 `verimap_links.json` 이다.
쿠팡은 검색 맥락(`q`·`sourceType`·`rank`)을 붙여야 열리는 상품이 있어 전부 붙인다.

## 7. 알려진 한계

**코드표가 같은 차종을 두 줄로 나눠 놓은 경우** — `해치백` / `해치백 S`,
`S클래스 7세대 전기형` 이 두 줄. 한 상품으로는 어느 줄인지 못 가린다.
6단계가 일부를 흡수하지만 모델명이 다르면 못 한다.

**채널 쪽 번호가 코드표에 없는 경우(고아)** — 오토바이 B번호는
오토바이 코드표가 비어 있어서 정상이다.

**쿠팡 productId 는 상품마다 고유하지 않다.** 등록상품 33개가 한 번호를 공유하는
경우가 있다. 구매 링크는 옵션 번호(itemId · vendorItemId)까지 붙여야 제대로 열린다.
