# 베리맵 상세 흐름 — 코드 단위

`베리맵_로직.md` 가 "왜 그렇게 짰는가" 라면 이 문서는 "무엇이 어떤 순서로 돌아가는가" 다.
함수 이름과 데이터 모양을 그대로 적었다.

---

## 1. 실행 단위

각 번호는 스크립트 하나를 통째로 돌린다. 베리맵 창이 `child_process.spawn` 으로 부른다
(cmd 메뉴 `베리맵.bat` 도 같은 번호로 같은 스크립트를 부른다). **스크립트끼리는 서로를 부르지 않는다.** 파일로만 주고받는다.

2026-10-27 창과 `.bat` 에서 해외몰 게시판 수집(18~20·22·23번)을 지웠다 — 아임웹 Open API 에 게시판이 없어 관리자 세션 크롤링으로만 읽을 수 있었다. 원본은 `../_삭제보관_20261027` 에 있다.

```
 1   verimap_load_codetable.mjs                         코드표
 2   verimap_collect_coupang.mjs --probe                연결 확인
 3   verimap_collect_coupang.mjs                        쿠팡 목록
 4   verimap_collect_coupang.mjs --detail --stock …     쿠팡 상세+재고
 5   verimap_collect_naver.mjs                          스마트스토어 목록   (Electron)
 6   verimap_collect_naver.mjs --detail …               스마트스토어 상세   (Electron)
 7   verimap_collect_imweb.mjs --diag                   아임웹 키 진단
11   verimap_collect_imweb.mjs --cat=내차찾기ver2         본사몰 상품
12   verimap_collect_imweb.mjs --site=b2b               B2B 상품
14   verimap_collect_imweb.mjs --site=b2b --options     B2B 옵션
15   verimap_collect_imweb.mjs --options --unit=…       본사몰 옵션
17   verimap_collect_imweb.mjs --cats                   본사몰 카테고리 목록
21   verimap_match.mjs                                  대조
```

21 은 네트워크를 전혀 안 쓴다. 나머지가 만들어 둔 파일만 읽는다.

## 2. 코드표 (1번)

```
loadConfig()      data/verimap/config.json 에서 시트ID·gid·탭이름
  ↓
fetchTab()        https://docs.google.com/.../export?format=csv&gid=…  → parseCSV()
  ↓
toEntries()       머리글에서 열 위치를 찾고(상품번호(코드표) · 제조사 · 모델명 · 세대 · 연식 …)
                  행마다 parsePartNo() · parsePartNos() · parseYears() · parseGen() · normBrand()
  ↓
codetable.json    entries[] + count + loadedAt
codetable_norm.csv   사람이 보는 용
codetable_except.csv 번호·연식이 안 읽힌 행 (현재 34행)
```

한 행은 이렇게 생겼다.

```json
{ "table":"자동차", "row":3, "partRaw":"No.101번",
  "partKey":"101", "partKeys":["101"], "partPrefix":"",
  "brand":"BMW", "brandRaw":"BMW", "model":"2시리즈", "modelAlt":"2 Series",
  "genNo":1, "genPhase":null, "genFacelift":null, "genRaw":"1세대",
  "ymStart":201404, "ymEnd":202107, "ymRaw":"14.04~21.07",
  "chassis":"F22/F23", "bsa":"" }
```

`row` 는 시트의 실제 행 번호다. 현황판이 이걸로 행을 가리킨다.
연식은 `YYYYMM` 정수로 눕힌다 — 비교가 뺄셈이 되도록. 끝이 열려 있으면 `999912`.

## 3. 채널 수집 (2~17번)

### 쿠팡

```
CoupangAPI (베리업 것)  ← HMAC-SHA256 서명, 초당 5회, IP 화이트리스트
  3번  목록    GET /seller-products            nextToken 페이징, 100개씩
  4번  상세    GET /seller-products/{id}       상품마다 1회  ← 차종(옵션)은 여기만 있다
       재고    GET /vendor-items/{vid}/inventories   옵션마다 1회
```

IP 화이트리스트 때문에 **관리자 서버(AWS 고정 IP)를 경유**한다.
`serverLogin()` 으로 토큰을 받고 `resolveRuntimeProxy()` 로 프록시 객체를 만들어
`CoupangAPI` 에 꽂는다. 베리업 파일은 고치지 않는다.

상세·재고는 각각 한 달 캐시(`coupang_detail_cache.json` · `coupang_stock_cache.json`).
목록만 받는 3번은 이전 `details` · `stock` 을 그대로 옮겨 담는다 — 안 그러면 21번이 멈춘다.

→ `coupang_raw.json` `{ collectedAt, vendorId, products[], details[], stock{} }`
→ `coupang_items.csv` `등록상품ID · 옵션ID · 옵션명 · 재고 · 판매중 · 판매가 · 판매상태`

### 스마트스토어

```
NaverStore + NaverAPI (베리업 것)  ← bcrypt 서명, IP 화이트리스트
  5번  목록  POST /external/v1/products/search
  6번  상세  GET  /external/v2/products/channel-products/{no}   ← 번호는 여기만 있다
```

**Electron 으로 돌려야 한다.** clientSecret 이 윈도 암호화 저장소(safeStorage)에
들어 있어 일반 node 로는 못 푼다. Electron 은 윈도에서 GUI 앱이라 cmd 에 출력이
안 보일 수 있어 `tee()` 로 `naver_log.txt` 에도 같이 쓴다.

→ `naver_raw.json` `{ products[], details[] }`
→ `naver_items.csv` `채널상품번호 · 옵션1_모델명 · 옵션2_상품선택 · 옵션3_좌우 · 옵션조합ID · 재고`

옵션 축 셋이 그대로 열이 된다. 번호는 `옵션2_상품선택` 안에 `[No.101]` 로 들어 있다.

### 아임웹 상품 (11·12·14·15번)

```
createImwebSession + createImwebClient (베리업 것)  ← OAuth2, 버킷 25 / 초당 2 회복
  11·12번  목록    GET /products?unitCode=…        페이징
  14·15번  옵션    GET /products/{no}/option-details   상품마다 1회
```

11번은 `--cat=내차찾기ver2` 로 **카테고리를 거른다.** 상품은 상위가 아니라
브랜드 하위에 붙어 있어 하위 전체를 포함한다(37개). 1,644 → 964개.

옵션은 `OPT_CACHE` 로 걸러 받는다. 열쇠가 `구역|상품번호|수정일` 이라
상품을 안 고쳤으면 다시 안 받는다. `optionRow()` 가 응답을 CSV 한 줄로 만들고,
축 이름은 `pickAxis()` 로 느슨하게 찾는다(`구성` · `구성 선택` 둘 다 잡히게).

→ `imweb_raw.json` / `imweb_raw_b2b.json`
→ `imweb_list.csv` `상품번호 · 상품명 · 판매상태 · 수정일 …`
→ `imweb_options.csv` `상품번호 · 옵션값전체 · 차종 · 연식 · 구성 · 재고`

## 4. 대조 (21번) — 실행 순서 그대로

### 4-1. 준비물 읽기

```
codetable.json        → CT (994행)
  byPart              Map(부품번호 → 행 배열)   partKeys 전부 색인
part_aliases.json     → ALIAS   구 번호 → 현행 번호
model_names.json      → MODEL_DICT { jp2ko(625), pair(1044) }
model_aliases.json    → MODEL_ALIAS
coupang_raw.json / naver_items.csv / imweb_list*.csv / imweb_options*.csv
```

### 4-2. 채널 데이터를 '적합 단위' 로 펴기

함수 네 개가 같은 모양의 레코드를 만든다.

```js
{ channel, productId, optionIds[], productName, optionText,
  model, state, form, forcedPart, multi, via, url }
```

```
coupangRecords()            상세의 items[] 마다 → 차종 1개
naverRecords()              naver_items.csv 행마다
imwebRecords()              imweb_list*.csv — 상품명에서 코드 추출, 짝 상품에서 물려받기
imwebOptionRecords()        imweb_options*.csv — 옵션이 있으면 이쪽이 우선
```

`state` 는 이 단계에서 정해진다. `notMirror()` → `isBundle()` → 판매상태 순.
`forcedPart` 는 "이 레코드의 번호는 이미 정해졌다" 는 뜻이다(상품명·옵션에서 뽑은 것).

현재 15,107줄.

### 4-3. 줄마다 사다리

```
state 가 '판매중' 으로 시작하지 않으면   → 통합상품 / 대상아님
  ↓
부품번호 정하기   forcedPart 또는 extractPart(옵션 → 옵션+상품명)
  없으면 → 미해결
  ↓
후보 모으기   byPart.get(번호)
  없으면 서브번호 떼고 재시도(H101-1 → H101)
  그래도 없으면 ALIAS(구 번호 → 현행)
  그래도 없으면 → 고아
  ↓
extractYears(연식) · parseGen(세대)   ← 옵션 텍스트 우선
  ↓
① take(후보, '부품번호 유일')          1행이면 확정
② 모델명으로 좁히기                    아래 4-4
③ 연식 일치 → 시작연도 일치
④ 세대 숫자 일치
⑤ 낱말 겹침                           딱 한 행만 걸릴 때
⑥ takeAll — 후보가 전부 같은 차종      모델명·세대가 같으면 전부 등록
  ↓
남으면 → 후보다중
```

`take(list, label)` 은 **list 가 정확히 1개일 때만** 확정 처리한다.
확정되면 `matched` 에 `표:행 → Set(채널)`, `forms` 에 칸에 적을 내용,
`links` 에 링크 번호를 넣는다.

### 4-4. 모델명 비교 (②)

```js
names = [ norm(rec.model), norm(jpToKo(rec.model)), ...dictNames(rec.model) ]
hit(e) = [ e.model, ...rowAltNames(e) ] 중 하나라도
           n === nmv  ||  nmv.includes(n)  ||  n.includes(nmv)
         (영문·일문 이름에 한해 앞부분 8자 이상 일치도 인정)

rowAltNames(e) = e.modelAlt
               + MODEL_DICT.pair["부품번호|국문모델명"] 의 en·jp
               + MODEL_ALIAS["부품번호|국문모델명"]
```

걸린 게 여럿이면 **제목 안에 통째로 든 이름 중 가장 긴 쪽**만 남긴다.
`해치백` 과 `해치백 S` 가 둘 다 걸릴 때 긴 쪽을 고르는 장치다.

`dictNames()` 는 가타카나가 든 제목에만 동작한다. 긴 이름부터 최대 2개.

### 4-5. 출력

```
match_현황.csv     carRows(994) × [고정 6열 + 채널 + 등록채널수]
                   채널 칸 = forms 에 모인 내용을 ' | ' 로, 3건 넘으면 '외 N건'
match_명단.csv     out[] 전부 — 판정·비고·추출값·코드표 행
match_링크.csv     코드표_행 · 채널 · 상품ID · 제목
match_미등록.csv   matched 에 없는 행
match_확인필요.csv  판정이 후보다중·고아·미해결인 줄
```

보고는 채널별 판매상태 분포 → 판정 분포 → 채널별 등록 수 순으로 찍는다.

## 5. 현황판 (src/ui/index_verimap.html)

`nodeIntegration` 이 켜진 렌더러라 메인 프로세스 IPC 없이 직접 돈다.

```
수집·대조 탭   버튼 = [번호, 이름, 실행기, 인자[], 예상시간]
               run()  → spawn(process.execPath, args, { ELECTRON_RUN_AS_NODE:1 })
                        네이버만 node_modules/electron/dist/electron.exe
               stdout 을 로그로 흘리고, 물어보는 줄이면 입력칸을 띄운다(askCheck)
               직원 아이디는 verimap_ui.json 에, 비밀번호는 메모리에만

현황 탭        loadStatus()  match_현황.csv → STATUS[]
               loadLinks()   match_링크.csv + verimap_links.json
               loadManual()  manual_links.json
               draw()        colgroup 에 px 폭을 박고(table-layout:fixed)
                             칸마다 channelCell() 로 그린다
```

`channelCell(r, c)` 의 우선순위.

```
수동 '누락' 표시 있음  → 빨간 '누락(수동)'
자동 값 없음 + 수동 'ok' → 초록 제목 + '수동' 꼬리표
자동 값 있음            → 초록 제목, 링크가 있으면 a 태그
자동도 수동도 없음       → 빨간 점 ·  (누르면 입력칸)
```

수동 표시 열쇠는 `부품번호|모델명|세대|채널`(공백 제거·소문자). 행 번호를 안 쓴 이유는
코드표에 행이 끼어들면 엉뚱한 차종에 붙기 때문이다.

## 6. 차종 하나를 끝까지 따라가 보기

`No.101번 BMW 1시리즈 2세대 12.03~19.05` (코드표 2행) 가 현황판 한 줄이 되기까지.

**1번** 시트 2행을 읽어 `{row:2, partKey:'101', brand:'BMW', model:'1시리즈', modelAlt:'1 Series', genNo:2, ymStart:201203, ymEnd:201905}` 로 만든다.

**3·4번** 쿠팡에서 `옵틱글래스 BMW 1시리즈 광각 사이드 와이드미러` 를 받고,
상세의 옵션 `No.101 (2세대/12.03~19.05)` 을 꺼낸다.

**5·6번** 스마트스토어에서 옵션 `BMW 1시리즈 / 12.03~19.05[No.101]` · `운전석` 을 받는다.

**11번** 본사몰에서 `옵틱글래스 BMW 1시리즈 광각미러 [No.101]` 을 받는다.

**12·14번** B2B 에서 `차종=1시리즈 / 연식=12.03~19.05 [No.101번] / 구성=운전석만` 을 받는다.

**21번** 네 레코드가 전부 번호 `101` 로 후보 14행을 받는다.
`① 유일` 실패(14행) → `② 모델명` 에서
쿠팡·본사몰·B2B 는 `1시리즈` 로 붙어 **2행 하나로 확정**된다.

**현황판** 2행의 네 칸이 전부 초록으로 차고, 각 칸을 누르면 그 상품이 열린다.

## 7. 고칠 때 건드리는 곳

| 하고 싶은 일 | 볼 곳 |
|---|---|
| 번호 표기가 새로 생겼다 | `verimap_match.mjs` 의 `RE_NO` · `RE_BRKT` · `RE_ALPHA` · `extractParts` |
| 매칭이 엉뚱하다 | 사다리 ①~⑥. `match_명단.csv` 의 `비고` 에 어느 단계에서 붙었는지 적혀 있다 |
| 연식·세대 표기가 새로 생겼다 | `verimap_load_codetable.mjs` 의 `parseYears` · `parseGen` |
| 품목을 더 걸러야 한다 | `notMirror()` |
| 일본 차종이 안 붙는다 | `model_names.json` 의 `jp2ko`, 또는 `model_aliases.json` |
| 링크가 안 열린다 | `verimap_links.json` (프로그램 수정 불필요) |
| 칸에 다른 걸 보여주고 싶다 | `cellText()` |
